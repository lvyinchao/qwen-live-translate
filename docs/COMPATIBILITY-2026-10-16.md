本轮覆盖 **24 个平台**：19 个平台检查公开页面，另 5 个订阅平台核验官方资料。最终在 **Bilibili、央视网、腾讯视频、芒果 TV、Facebook、Twitch** 各至少有一条样本通过严格暂停音频预读；腾讯、芒果后置观察不稳定。优先补齐可见正片的媒体归属与取源时序，不能把“发现视频”当作“可翻译”。

本次评估不修改扩展运行代码、权限、模型、用户配置或 Chrome 安装，也不调用翻译模型。它回答“当前扩展能否从网页取得可提前解码的音频”，不代表新增原音色译音、同步、语言质量或连续观看验收。历史真实译音证据及其构建、缓冲与截尾限制见[完整验收记录](VALIDATION.md)。

## 如何阅读结果

- **样本预读通过**：已核对正片；播放器暂停，使用扩展自己的解码 Worker 读取前段和中段两个窗口，取得有限值的单声道 16 kHz PCM，覆盖请求时间，解码前后播放位置稳定。只适用于列明的页面、入口和访问条件。
- **已复现适配缺口**：正片播放器已存在且可播放，扩展因资源归属歧义等明确原因拒绝选轨。单列“看见播放器”“发现候选地址”“选中来源”“得到 PCM”，不将它们互相替代。单次网络错误、读取超时、元数据未就绪或审计暂停条件未满足，均按具体未读通条件记录，不直接归因于适配器缺陷。
- **访问/环境未验证**：登录、真人验证、App 引导、播放器未完成初始化等条件使本轮无法测到正片。不能据此断言整个平台不兼容。
- **资料评估**：仅核验官方帮助或协议，没有播放订阅正片。已识别的受保护媒体不在当前解码路径内；`blob:`、VIP 标签、MSE、HLS/DASH 或防盗链本身都不能证明 DRM。

## 当前应优先改进的地方

1. **优先修正多资源与播放器的归属。** 在爱奇艺、搜狐等可见正片样本中，扩展能看见视频，也观察到媒体请求，但会因资源归属歧义而拒绝选轨。多份资源具体是否来自清晰度子清单、广告或其他播放器，仍需逐站核验。这是比继续增加域名匹配更具体的工作。应以当前内容身份、当前播放器、原生请求和时间线建立关联；若确认同属 HLS 主清单，再合并子变体并核对时长，不能直接取第一条请求。
2. **区分媒体发现状态与失败原因。** “找到候选但元数据未就绪”“多个资源归属不明”“站点要求登录”“扩展读取返回 HTTP 错误”需要分别呈现。侧栏持续检查已有机制，重复扫描本身不能消除归属歧义。
3. **补齐明确的清晰度、广告结束和页面切换用例。** 明文样本成功后，继续测两个不同内容、晚打开侧栏、广告结束、换集、同页导航及签名续期，再做真实译音长测。本轮较短 PCM 窗口不能替代这些用例。
4. **将 YouTube 播放验证单独列为兼容性工作。** 本轮匿名访问条件与历史 SABR 读取限制分开记录；历史部分窗口成功不等于持续可用，不应对登录后的能力作未经测试的承诺。
5. **通用 DASH 解析和订阅服务分开规划。** 当前通用来源选择没有完整 DASH 音轨解析器；补充未加密 DASH 的清单、轨道身份及时间戳处理可能扩大覆盖，但不会使 DRM 正片变成可独立解码音频。

## 复现方法与证据边界

使用 macOS arm64、Chrome for Testing 156.0.8078.4，每个样本创建新的匿名浏览器配置，加载上面精确哈希的扩展。没有复用用户 Chrome 的登录、模型密钥、历史缓存或本地归档。部分补测使用正常可见窗口，单独标注，不改变浏览器自动化特征、不完成真人验证或登录。

每个公开页面分别测试：

1. `early`：页面导航前启动面板观察租约，模拟先打开扩展。
2. `late`：页面加载并尝试原生播放，再等约 5 秒后启动观察，模拟导航后才打开扩展；没有覆盖观看几十分钟后才打开侧栏。页面有时尚未就绪，失败不能一概归因于遗漏媒体请求。
3. 发现最多扫描三轮，未就绪时两轮间隔 2.5 秒；页面在扫描结束后才初始化，不代表持续观察永远无法发现。每窗最多 8 秒，第一窗约从 3 秒开始，中窗从半程或 1180.15 秒开始；短片按时长缩小窗口。主视频暂停后解码，读取结束的状态采样不再主动暂停。检查时间戳覆盖、16 kHz 输出数量、有限 PCM、静音情况和视频时间变化；这是前后状态检查，并非逐毫秒的全程暂停监视，也不是完整音频无空洞或听感质量检测。
4. 最终确认使用与生产相同的 60 秒单窗预算，并在两个窗口间复用同一个 Worker，保留顺序下载/Range 缓存。超出读取预算只能说明该次未读完，不能推广为平台永久不兼容。
5. 正常等待贴片结束、点击已经观察到的普通播放/继续浏览器控件等补测单列。爱奇艺“继续使用当前浏览器观看”的正常点击超时，未成功点击，也没有强制点击。没有购买会员、付费跳广告或突破保护。

脚本直接调用真实解码 Worker，未启动完整译音会话及生产 Player 的 `play`/缓冲暂停监听。因此页面初始化时出现迟到的自动播放，会使本审计“保持暂停”条件失败；应保留该失败，不能直接推断完整扩展会话也无法暂停或同步。新 Bilibili 前置观察有一次双窗 PCM 完整但首窗期间原页面开始播放，不计该次暂停预读通过。

初筛脚本的 35 秒预算、每窗重建 Worker 以及暂停状态读回方式在独立审查中被发现会影响判断，因此初筛保留为诊断，所有据以宣称“样本预读通过”的项均以 **schema 3** 复核。静音窗口单独记录，不因真实静音直接判失败；至少另有非静音窗口才确认已获得有声节目音频。正片归属由标题、时长、原生状态和截图人工核对，不依赖通用适配器的 `ad=false`。全页 `drmObserved` 只表示某个框架的保护信号，不能直接归给所选正片。页面关键词同样只是线索。

自动化日志不含模型密钥、Cookie、请求头或完整签名媒体地址；保留公开观看 URL、媒体主机、类型、HTTP 状态及数值结果。截图在本地 `output/playwright/`，默认不随报告发布。原始结果中的截图路径指向本地证据，并非公开图片下载地址。

单项可按 JSON 中 `attemptId` 定位。`strictPcmCheckPassed` 是媒体预读结论；人工标题、时长及画面核对见 `manualDomesticReview` / `manualGlobalReview`。`sourceSelected=false` 不必然表示从未发现地址，例如 Twitch 初筛和 Vimeo 官方入口有候选但尚无有效时长。两条标记 `interruptedByAuditor` 的记录，以及看门狗导致的 `timedOut`，不能当作解码能力失败。

可重复的手工审计脚本：[audit-platforms.mjs](../scripts/audit-platforms.mjs)。输入是公开观看页面的 JSON 数组，`platform`、`url` 必填；可选 `mode`、`minDuration`、已观察到的 `playSelector`、`settleMs`、`controlAfterSettle` 和 `inspectControls`。例如以 Bilibili 为例：

```json
[
  {
    "platform": "Bilibili",
    "url": "https://www.bilibili.com/video/BV13rsaeaEgE/",
    "mode": "early",
    "minDuration": 100
  }
]
```

```sh
node scripts/audit-platforms.mjs work/spec.json work/report.json
# 正常可见浏览器对照；默认无界面。
AUDIT_HEADLESS=0 node scripts/audit-platforms.mjs work/spec.json work/report-visible.json
```
