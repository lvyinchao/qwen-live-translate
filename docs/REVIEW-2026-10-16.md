## 第二轮复审补充

缩小观察范围后，再次检查了新的异步边界，补充修复了以下路径：

- **释放后晚到响应**：存储读取或请求处理等待期间关闭面板、租约过期、导航或换页后，旧响应不得重新写入媒体地址。观察代际在异步边界前后校验。隔离故障注入已确认释放后无候选重新进入内存或会话存储；回归见 [`media-observer.test.ts`](../tests/media-observer.test.ts) 及 [`observation-scope.test.ts`](../tests/observation-scope.test.ts)。
- **终止状态残留**：为诊断保留的 `error` / `ended` 会话不能继续取得观察租约；没有面板时释放终止任务的标签。
- **同页响应乱序**：较旧的 native 响应在等待任务停止后不得覆盖较新资源；generic 响应等待存储后重新读取最新内存状态，避免旧快照覆盖新候选。
- **HLS 身份边界**：相同片段 URL 但不同 `EXTINF`、`MEDIA-SEQUENCE` 或初始化资源仍是不同时间线；身份保留清单标签，并规范化其中的资源 URI。
- **腾讯元数据先到**：面板打开前已出现的页面元数据，通过显式发现请求重放最新内容；未因关闭观察而要求用户必须刷新页面。重放仍经过当前观察范围及媒体身份校验。
- **设置并发复活旧密钥**：界面语言和保存开关等操作此前会读取整份设置后回写；并发“移除凭据”或替换凭据时，晚到的旧快照可能复活旧密钥或覆盖新地域。后台现在串行处理全部设置读改写，六项新增定向回归覆盖删除前后及凭据替换时的两类偏好更新。见 [`background-lifecycle.test.ts`](../tests/background-lifecycle.test.ts)。
- **YouTube 直链音轨身份与 fallback 选轨**：此前直接媒体来源的轨道身份可能退回固定 `default`，而备用选流未按当前音轨筛选，存在不同音轨误用缓存的路径。追加修复将来源、缓存身份与当前音轨关联，限制备用选流及观察来源替换，相关错误支持中英文。回归见 [`youtube-audio-track.test.ts`](../tests/youtube-audio-track.test.ts)、[`youtube-audio-observer.test.ts`](../tests/youtube-audio-observer.test.ts)；这些隔离检查不代表 YouTube 持续翻译通过。
- **实际起播超标**：初版真实短片记录虽完成控件操作，eligible 起播 P95 仍超过 300 ms。此结果没有算作同步验收通过；随后增加完整语句预加载及 50 ms 调度检查。最终结论必须使用该修改之后的新构建与新实测，不能沿用旧结果。
- **短尾真实截停及分类盲区**：理想音频位置已到末尾而实际媒体元素仍剩几十毫秒时，旧分支会提前暂停/跳过。恢复旧分支后，60 ms 短尾回归必然失败；修复后在源句边界前允许真实短尾自然结束，到源句边界仍须截停，但任何正的剩余量都记录，不能只统计大于 100 ms。见 [`player-tail.test.ts`](../tests/player-tail.test.ts)。
- **终止事件可靠性与诊断保留**：每条已起播语句记录自然结束、时间线/重叠截停、跳转、换语言、停止/错误、视频结束或播放器丢失原因；常规消息与生命周期确认去重交付，并校验所属任务及版本。关键指标环与详细调试环分别保留，调试流不能挤掉起播、终止或模型确认，溢出量单独计数。13 项新增播放器回归覆盖旧短尾分支、终止交付及事件环，实际媒体播放另由浏览器门禁检查。
- **标题语言联动**：面板产品标题、页面标题及工具栏提示跟随保存的 English / 简体中文偏好，已在真实翻译与本机 Chrome 双语切换中确认，并恢复原中文偏好。Chrome 扩展管理页名称和侧栏外框标题由 Chrome 浏览器语言决定，不能通过插件界面偏好在运行时更改。

## 升级与已有本地数据

- 使用原有扩展条目及稳定安装目录更新/重新加载；不要通过卸载再安装来期待自动继承原扩展的私有数据。0.2.2 安装 ZIP 根目录可直接加载；旧版嵌套目录说明仍保留在双语安装指南中。
- 凭据、语言、界面及保存偏好继续使用原本的受限本地存储。新安装或未设置过的自动保存偏好仍为关闭；已有用户明确开启的偏好会保留。
- generic 视频的新身份用于隔离不同媒体和框架；不能安全确定归属的旧页面级缓存不会强行套用到新视频，可能需要重新准备。已有播放缓存仍受容量限制，可在设置中清除。
- YouTube 的直链与备用来源也必须以当前音轨关联身份；旧 `default` 身份不能作为跨音轨缓存复用的依据，修复后可能需要重新准备该轨道。
- 旧归档队列先完成 WAV 和索引写入再删除旧队列项；启动时修复近似重复索引并回收无引用文件，保留同时说话的片段。先前失败的下载只在用户显式重试后重新发起，打开面板不会触发下载队列。
- 已下载 ZIP/WAV 不会因升级、缓存清除或归档清理而被删除；归档清理仅作用于扩展私有暂存。若旧版本已经把不同视频内容错误混到同一归档，无法从缺失的身份信息可靠自动拆分，需用户核对并清除该旧归档后重新翻译。

### 真实验收记录口径

- 起播以视频 `currentTime` 减模型源语句起点，在译音触发 `playing` 时观测；eligible 排除跳入半句和已跳过尾部。另列全部起播、有效样本、排除原因及跳过比例，避免只展示有利样本。句末采用自然结束的独立样本，截断和跳转中止不算自然结束。
- 300 ms 目标是 eligible 起播的 P95，必须伴随样本数、句末偏差及终止分类覆盖率。历史缺失不可重建。当前长例有 67 个自然终止分类及 63 个 native-ended 指标，两个计数原样保留；句末有符号 P50 −284.464 ms 含短句提前完成后的留白，绝对 P95 949.919 ms 不能解释为纯滞后。新格式记录所有正剩余截尾、区分用户停止与时间线截停，未知仍为未知；本次关键丢弃 0，1516 条调试记录滚动丢弃不能冒称保留了全部调试历史。软件度量不等于硬件回采或音色相似度验收。
- 长时缓冲占比来自采样，首次准备、用户操作等待及连续观看分别记录。没有长时采样的短片不得填成零缓冲、零内存的长时结果。
- 费用按供应商会话的累计 usage 去重后估算，并说明地域、单价和未完成响应的缺失。输入音频小时、源视频观看小时及实际等待墙钟小时是不同分母；缺失 usage 不能表述为免费，估算不是账户账单。
- 只接受明确的真实页面/模型报告作为真实验收，合成夹具、旧构建、未知来源及失败报告单独标注。最终发布使用的构建哈希应与新实测及发行包对应。

## 保持的产品选择与未覆盖项

原声音色模式继续开启，仍可能受录音质量、说话人及语言影响；不承诺逐字口型同步。无自建后端：用户自行到 [qianwenai.com](https://qianwenai.com/) 注册并申请 API Key，凭据保存在扩展受限本地存储，由供应商计费。自动本地文件保存仍默认关闭，启用后静默分段暂存再合并；播放缓存与可选归档分别管理。

全屏结论仅覆盖已测试的网页播放器按钮打开的容器全屏。视频元素自身调用 `HTMLVideoElement.requestFullscreen()` 时，字幕叠层不能进入它的顶层；这种原生视频全屏字幕及画中画（PiP）字幕暂不支持。不能将容器全屏通过写成所有全屏或画中画模式通过。

继续采用暂停预读、提前译音和原网页播放器时间轴。没有恢复延迟采集兼容模式，也没有新增直播、DRM 解密、移动端或所有网站保证。Bilibili 的实测不替代尚未完成的 YouTube 长时翻译；发现可见播放器或媒体请求也不等于能获取完整可解码音轨。Chrome 商店提交、审核和公开可安装状态仍与 GitHub 安装包分开记录。
