# 听译 · Qwen Video Dub

Chrome 自用扩展（原音色译音）：在原网页播放器上，播放跟随视频时间轴的 Qwen 译音和双语字幕。另有采集标签页画面与声音、在独立窗口延迟同步播放的兼容模式。无需自建后端，使用自己的百炼账户。

> 当前为功能预览版：Bilibili 已通过中英双向的原网页播放检查；YouTube 可读取部分片段，但长视频后续音轨遇到播放验证限制，尚未通过连续译音验收。完整状态见 `真实验收记录.md`。

## 安装

1. 解压 `听译-Chrome-0.1.5.zip`，保留完整文件夹。
2. 打开 Chrome 的 `chrome://extensions`，打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹。
4. 将“听译”固定在工具栏，刷新已打开的视频页面。
5. 点击扩展图标，在侧边栏设置里填写 API Key、Workspace ID 和对应地域，保存后验证连接。

安装时会提示访问网站及标签页采集权限。Chrome 对请求头修改同时检查目的地址和发起方；真实验证表明，窄域名声明不足以给扩展自身的 WebSocket 握手添加鉴权头，因此使用 `<all_urls>` 主机权限。运行时内容脚本可检测普通 HTTP/HTTPS 网页及 iframe 中的播放器；媒体探测覆盖公开 HTTPS CDN 的文件、HLS、DASH 和分片；鉴权规则仅作用于扩展自身访问指定的百炼模型地址，不会给视频网站附加模型密钥。

## 使用

界面支持 English / 简体中文，首次打开默认为英文；通过侧边栏右上角的语言选择器即时切换，选择会自动保存在本机。界面语言与“翻译成”的视频目标语言独立，视频目标语言仍默认中文。移除 API 凭据不会重置语言偏好。

打开普通点播视频，先播放几秒，让扩展识别音轨。在侧边栏选择视频和目标语言，点击“开始翻译”。扩展会暂停原视频，先准备约 30 秒的译音，再自动继续播放；此后边播放边准备后续内容。实际等待取决于网络和模型，不能用官方同传延迟当作首次准备时间。

- 原视频默认静音。可分别调整原声和译音音量；降低原声也会降低原片中的音乐。
- 暂停、恢复、跳转和 0.5～2 倍速跟随原播放器。
- 数据尚未就绪时暂停缓冲。长译音最多以 2 倍速度播放，仍赶不上时跳过过期部分，保持画面连续，字幕保留完整译文。
- “停止翻译”恢复开始前的原声音量和静音设置。
- 设置页可清除最多 128 MiB 的译音缓存及本机凭据。

模型为 `qwen3.8-livetranslate-flash-realtime`。只发送音轨，不发送整段视频或画面。默认启用 Qwen 的实时音色复刻，随原说话人生成译音。模型复刻完成前可能使用默认音色过渡，不能承诺音色完全一致。扩展会校验服务端是否确认启用音色复刻；未确认则停止并提示。原音色缓存与系统音色缓存隔离。配置依据：[百炼客户端事件文档](https://help.aliyun.com/en/model-studio/live-translator-client-events)。

API Key 不放入网页、Chrome 同步存储、源码或发行包。译音和字幕会缓存在这台浏览器的 IndexedDB 中，费用由百炼账户结算。

## 视频网站与音轨读取

0.1.4 开始，除 YouTube / Bilibili 专用适配器外，加入优酷、爱奇艺、腾讯视频等网站的通用检测：扫描当前页、iframe 和开放 Shadow DOM 的视频，并观察实际媒体请求。可匹配的完整媒体文件和未加密 HLS 点播可交给解码器提前读取；未找到播放器时仍列出已发现的媒体请求并标记暂不可翻译；多个资源无法确定归属时明确提示，不把其他播放器或广告音轨直接配给当前视频。通用检测不等于这些网站所有影片均已通过翻译验收。腾讯另有旧版明文播放信息内嵌 HLS 的解析；新版编码播放信息尚未适配，该路径目前仍可能无法提前翻译；0.1.5 兼容播放器已通过用户提供的腾讯视频短段中文→英文译音检查。

DASH 清单、独立分片和带 MediaKeys 的受保护播放器会显示发现状态及具体限制。当前没有通用 DASH 清单解析，也没有 DRM 解密路径。原网页预读模式只有取得可提前读取的音轨后才可翻译；兼容模式另见下节。特殊播放器和闭合 Shadow DOM 仍可能需要站点适配。

对于忽略 HTTP Range、始终返回整份文件的服务器，0.1.4 把已读原始媒体字节暂存至扩展的临时本地文件，供解码器回读，内存缓存保持 8 MiB。后续窗口复用该响应；工作线程退出后，下次创建临时媒体文件时回收遗留文件。单份兼容音轨上限 2 GiB，同时最多保留两份，空间不足、数据不完整和超时均会报错。此类服务器可能要求顺序读完整份音轨才能开始，准备时间取决于文件大小与网络。这些临时文件与永久译音分段分开，不弹下载窗口。

关闭“双语字幕”会立即隐藏扩展生成的字幕；后续片段、全屏和播放器状态更新遵循该开关。原片画面内嵌的字幕仍会保留。

## 兼容播放器（0.1.5）

当网站能正常播放，但扩展无法提前读取音轨时，可选择视频和目标语言，点击“用兼容播放器翻译”。首次使用或切换网站后，请在视频所在标签页点击一次扩展工具栏图标，Chrome 才会授予这次标签页采集权限。

原标签页继续提供画面和声音，Chrome 会抑制该标签页对外播放的原声；请保持视频位于页面可见区域，并暂停同一标签页中其他正在播放的媒体，避免混入其声音。扩展录制标签页可见画面和声音，在独立窗口延迟播放录制画面与对应的原音色译音。采集的是标签页画面，可能包含网页播放器周围的内容；想只看视频画面，可先在站点播放器开启“网页全屏”（铺满标签页）。不捕获浏览器工具栏，也不上传画面到模型。首次先录制 30 秒，再进行翻译，通常需一分钟或更久；不足 30 秒的尾段在原视频播放结束后提交。画面与译音共同延迟，原网页中的实时画面与兼容播放器不处于同一进度。

- 暂停、恢复、0.5～2 倍速、全屏、原声/译音独立音量和双语字幕开关在新窗口控制。译音最多 2 倍速，长句过期尾部跳过，完整译文保留。
- 只能在当前已经翻译、仍在播放器缓冲中的范围内跳转，保留约两分钟已观看画面；不能跳到尚未采集的任意远处。要换位置，请先停止，在原网页跳转后重新开始。
- 后台优先准备后续译音；未翻译积压超过约 65 秒，或采集领先观看超过约 90 秒时，自动同时暂停原播放器与录制，释放积压后恢复。播放缓冲不足时，新窗口暂停等待。
- 临时录制画面分段静默写入扩展本机目录，单次最多 2 GiB；达到上限会停止并提示，不无限占用内存。停止或关闭兼容窗口会释放采集、恢复原播放器设置、清理临时录制；原网页保留已经采集到的进度，想接着新窗口的位置观看时需手动回退。下次开始还会回收意外退出的残留临时文件。已完成的译音和脚本保留并合并保存。
- 兼容模式脚本中的源时间以本次录制起点为零，`trackId` 标明原网页开始位置。网页缓冲或停顿会保留为录制时间，不能把录制时间直接等同原视频进度。
- 切换原网页视频、原网页跳转进度或播放器被替换会结束当前任务，防止混入不同内容。带 DRM 的播放器仍不支持；某些网站可能阻止录制并产生黑屏或无声，这类页面需要实际核验。

此模式独立于“开始翻译”的原网页预读模式，需要用户主动选择。它不承诺原网页实时画面与译音零延迟；真实网站、较长播放和语音同步的已测范围见 `真实验收记录.md`。

## 保存到本地

从 0.1.3 开始，译音先静默分段保存在扩展的本机专用文件目录（OPFS）。分段不会发起下载，也不打开保存位置选择器；跳转和重开侧边栏同样不会启动下载。此前 0.1.2 的待保存队列会迁移到本机分段目录，已下载的旧文件保留。

翻译完成、停止或失败退出时，按视频、目标语言与音色把已完成的语句合并，只下载一个最终 ZIP 到 Chrome 设置的下载目录下 `Qwen Video Dub/` 文件夹。也可在侧边栏点击“合并并保存”。相同内容不重复下载；合并中断后保留片段，用户点击重试时才重新下载。重开扩展不会反复重试已取消的保存。

每个合并包包含可连续播放的 `combined.wav`、与该音频时间对应的 `combined.srt`、使用原视频时间的 `source-subtitles.srt`，以及双语 `transcript.txt` / `transcript.json`。WAV 按源视频顺序拼接完整的 24 kHz 原音色语句，不变速、不截尾，不拼接 WAV 文件头。句间空白和未翻译的源视频区间不放入合并音频，JSON 同时记录源视频时间和合并音频时间；未完成整段视频不会标为已完成。

片段保存在本机专用目录中，合并 WAV 和 ZIP 也按流写盘，不把整段长视频音频一次性装入 JavaScript 内存。播放缓存的 128 MiB 上限不再限制归档片段；归档使用浏览器允许的本地磁盘空间，空间不足会明确报错。清除播放缓存或 API 凭据不会删除已暂存片段和已下载文件。卸载扩展或清除此扩展全部站点数据会移除其内部片段，已下载的文件仍由你管理。

保存过程使用[浏览器专用本机文件系统](https://web.dev/articles/origin-private-file-system)，不更改 Chrome 全局下载设置，不关闭浏览器的安全检查，不上传到额外服务，也不包含密钥、签名媒体地址或请求头。如果 Chrome 开启了“下载前询问每个文件的保存位置”，最终合并包仍会询问一次；分段阶段不询问。系统或浏览器对最终文件的必要安全提示仍由 Chrome 控制。

## 范围

首版面向桌面 Chrome 116 及以上版本和普通点播。原网页模式需要可预取的独立音轨；兼容模式需要可采集的标签页画面和声音。直播、DRM、音乐人声分离、独立声音复刻管理、原视频下载导出和移动端未包含。网页和 CDN 可能变化；原网页预读模式无法获取音轨时明确报错；用户可另行选择带画面延迟的兼容播放器，不会自动切换模式。

同步指语句与媒体时间轴关联，不承诺逐字口型同步。真实验收状态请以随包的验收记录为准，构建通过不等于站点或长视频测试通过。

## 开发与验证

需要 Node.js 22 或更高版本；ZIP 交付与归档测试使用系统的 `zip` / `unzip`（macOS 自带）。

```sh
npm ci
npm run check
npm test
npm run build
npm run zip
# 交付预览包（先生成真实验收记录）
node scripts/package.mjs
```

构建目录为 `.output/chrome-mv3`。可加载该目录调试；仓库中的 `work/` 为研究与隔离测试材料，不进入发行包。

浏览器验收脚本使用 Playwright 的独立配置目录及 Chrome for Testing，不修改常用 Chrome 的配置。兼容采集验收脚本 `scripts/gate-capture.mjs` 还需要系统 `ffmpeg` 来生成带语音的测试视频；`HEADLESS=1 NORMAL_AUTOPLAY=1 node scripts/gate-capture.mjs` 检查默认自动播放规则，`HEADLESS=1 CAPTURE_SECONDS=100 BACKPRESSURE=1 node scripts/gate-capture.mjs` 检查缓冲暂停/恢复。二者会真实调用模型。脚本通过浏览器根 CDP 会话加载扩展；生产扩展不使用 `debugger` 权限或调试协议。`gate-browser.mjs` 当前从本机百炼 CLI 配置读取测试凭据，仅适用于本机验收，不会把该配置复制进发行包。

## 依赖与许可

本扩展为独立实现，没有复制 FetchV 的代码。使用 WXT、React、Lucide、Mediabunny 和固定版本的 googlevideo。YouTube SABR 音轨读取基于 googlevideo；Bilibili 使用播放器实际请求的独立音轨。Mediabunny 1.61.4 使用 MPL-2.0，保留其许可及来源说明；见发行包 `THIRD_PARTY_NOTICES.md`。安装包不从第三方网站动态加载执行脚本。
